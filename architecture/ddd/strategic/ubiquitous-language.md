# Ubiquitous Language (универсальный язык)

Язык домена = язык кода = язык документации = язык общения команды.
Типы, методы и переменные называются **терминами, которые используют доменные эксперты**.

**Когда использовать** — всегда (даже на уровне 0, в миниатюре); критично при DDD ≥ 1.
**Когда НЕ использовать** — нигде: это не опция, а гигиена.

## Примеры

| Доменный термин | ❌ Плохо | ✅ Хорошо |
|---|---|---|
| Заказ подтверждён | `order.setStage(2)` | `order.Confirm()` |
| Клиент сделал возврат | `item.returnFlag = true` | `customer.RequestReturn(orderID, reason)` |
| Сумма заказа | `order.total` (float) | `order.Total() money.Money` |
| Просроченный счёт | `invoice.isLate == true` | `invoice.IsOverdue(now)` |

## Правила

1. **Глоссарий в репозитории**: `docs/glossary.md` — термин, определение, владение (какой контекст).
2. **Один термин — одно понятие**: если «заказ» и «заявка» — разные вещи, они должны так и называться.
3. **Код читается как домен**: `if invoice.IsOverdue(now)` вместо `if time.Since(inv.date) > 30d`.
4. **Обсуждайте с экспертами**: имена методов — часть доменного моделирования, а не стилистика.

## Процесс

1. Собрать экспертов и разработчиков (event storming / domain modeling).
2. Зафиксировать термины и определения (глоссарий).
3. Имена в коде — только из глоссария; новые термины — сначала в глоссарий, потом в код.
4. Ревью: «как это звучит для доменного эксперта?»

## Антипаттерны

- ❌ «Перевод» между слоями: в UI — «заказ», в коде — `OrderDTO.stage=2`, в БД — `ord_stat`.
- ❌ Технические термины в домене: `entity`, `record`, `handler` вместо доменных слов.
- ❌ Глоссарий, который никто не читает и не обновляет.
