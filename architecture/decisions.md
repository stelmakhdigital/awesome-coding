# Архитектура — таблицы решений

## Проект → архитектура

| Проект | Рекомендация | Альтернатива | Когда |
|---|---|---|---|
| Скрипт / CLI-утилита | без архитектуры: функции + пакеты | — | — |
| CRUD-сервис, простой домен | [layered](patterns/layered.md) (handlers → services → repositories) | — | — |
| Бизнес-логика в ядре, сложные инварианты | DDD уровень 1 + [hexagonal](patterns/hexagonal.md) | layered с «толстыми» сервисами | инварианты нарушаются в сервисах |
| Несколько доменов / команд | DDD уровень 2 + [modular monolith](patterns/modular-monolith.md) | микросервисы | только после монолита |
| Независимое масштабирование частей | [microservices](patterns/microservices.md) | modular monolith | границы выделены, команды готовы |
| Асимметрия чтения/записи | [CQRS](patterns/cqrs.md) | — | нагрузка на чтение ≫ запись, разные модели |
| Аудит / история изменений состояния | [event sourcing](patterns/event-sourcing.md) | append-only лог в БД | финансы, критичные состояния |
| Интеграции, отказоустойчивость | [event-driven](patterns/event-driven.md) (outbox) | прямые вызовы | надёжность, слабая связанность |

## Уровень DDD

| Сигнал | Уровень |
|---|---|
| CRUD, тонкая бизнес-логика, «просто CRUD» | 0 |
| Сложные инварианты, доменные правила, поведение в данных | 1 |
| Несколько команд/доменов, у одного слова разные значения | 2 |
| Распределённые события, аудит, высокая нагрузка на чтение | 3 |

## Анти-решения (не делайте)

- ❌ DDD для CRUD: сущности без поведения и агрегаты без инвариантов — оверхед без пользы.
- ❌ Микросервисы с нуля: начните с modular monolith, делите, когда границы станут очевидны.
- ❌ CQRS «на всякий случай»: только когда модели чтения и записи реально расходятся.
- ❌ Event sourcing «для масштабируемости»: сложность проецирования не окупается в большинстве доменов.
- ❌ «DDD-lite»: переименованные папки (domain/infrastructure/application) без поведения в модели.
