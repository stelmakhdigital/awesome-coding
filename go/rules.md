# Go — Rules

Обязательный набор правил. ✅ — делать, ❌ — не делать.

## Ошибки

- ✅ Оборачивайте ошибки с контекстом: `fmt.Errorf("open %s: %w", path, err)`.
- ✅ Проверяйте каждую возвращаемую ошибку; обрабатывайте на уровне, который может что-то с ней сделать.
- ✅ Сравнивайте через `errors.Is` / `errors.As`, а не `==` (кроме своих sentinel'ов внутри пакета).
- ✅ Текст ошибки: lowercase, без точки в конце, без префикса «Err» в строке.
- ❌ Не игнорируйте ошибки: `_ = f()`.
- ❌ Не `panic` в library-коде; panic — только для невозвратных состояний (сломанный инвариант, паника при старте с невалидной конфигурацией).
- ❌ Не возвращайте ошибки строками и не логгируйте «на всякий случай» вместо возврата.

## Именование

- ✅ Пакеты: короткие lowercase слова (`user`, `storage`), без camelCase и подчёркиваний.
- ✅ Receiver'ы: 1–2 буквы — аббревиатура типа (`s` для `Server`), одинаковые внутри одного типа.
- ✅ Экспортируйте только то, что должно быть публичным; остальное — lowercase.
- ✅ Переменные, функции, типы: `mixedCaps` (`maxRetries`, `GetItem`); константы — тоже `mixedCaps` (`MaxRetries`, не `MAX_RETRIES`).
- ✅ Аббревиатуры — единообразно: `HTTPClient`, `ParseURL` (не `HttpClient`, `ParseUrl`).
- ❌ Нет подчёркиваний в именах (в т.ч. для «приватного» — lowercase уже приватный).
- ❌ Не дублируйте имя пакета в имени: `user.UserService` → `user.Service`.
- ❌ Нет пакетов `util`, `common`, `helpers`, `misc` — выносите по смыслу.

## Конкурентность

- ✅ `context.Context` — первый аргумент, имя `ctx`; не храните в структурах.
- ✅ У каждого goroutine должен быть путь завершения (ctx, канал, WaitGroup).
- ✅ Общий мутабельный state — за mutex'ом или в одной goroutine; документируйте, что защищает.
- ❌ Не запускайте goroutine «на всякий случай» без механизма завершения.
- ❌ Не передавайте данные, разделяя каналы, когда достаточно mutex'а (и наоборот).
- ❌ Не `time.Sleep` в production-коде «в ожидании чего-то» — используйте условия/сигналы/ctx.

## Функции и структура

- ✅ Маленькие функции; если нужно объяснять — выносите.
- ✅ Early return (guard clauses) вместо вложенных if.
- ✅ `defer` для cleanup (close, unlock, временные файлы) — сразу после успешного получения ресурса.
- ❌ Не передавайте «структуру всех параметров» — используйте интерфейс или functional options.

## Импорты

- ✅ Группы: stdlib / внешние / проект (goimports).
- ✅ Предпочитайте stdlib (см. [decisions.md](decisions.md)).
- ❌ Нет «запасных» импортов, которые не используются.

## Тесты

- ✅ Table-driven тесты, subtests с осмысленными именами.
- ✅ `t.TempDir()`, `t.Setenv()`, `t.Parallel()` где уместно.
- ❌ Нет зависимости от порядка тестов и глобального состояния.
- ❌ `t.Fatal` в goroutine (используйте `t.Errorf` + канал/WaitGroup).

## Производительность (только по бенчмаркам)

- ✅ Предварительное выделение: `make([]T, 0, n)`, когда размер известен.
- ✅ `strings.Builder` для конкатенации в цикле.
- ❌ Не оптимизируйте без `go test -bench` (и без профилировщика для hot path'ов).
