# PM — проектный и продуктовый менеджмент

Скилл проектного/продуктового менеджмента для кодинг-агентов: SDLC начиная с discovery,
PMBOK (5 групп процессов, 10 областей знаний), сбор требований, риски, и два
рабочих файла проекта:

- **`roadmap.md`** — фазы и задачи проекта, статусы, решения (обновляется по ходу).
- **`PROJECT_MEMORY.md`** — долгосрочная память проекта: контекст, люди, решения,
  ограничения (переживает смену сессий/агентов).

## Записи

| Тема | Файл |
|---|---|
| SDLC (фазы, гейты, артефакты) | [sdlc.md](sdlc.md) |
| PMBOK (группы процессов, области знаний, charter, RACI) | [pmbok.md](pmbok.md) |
| Discovery (валидация проблемы) | [discovery.md](discovery.md) |
| Требования (интервью, MoSCoW, user story, NFR) | [requirements.md](requirements.md) |
| Опрос (готовый шаблон вопросов) | [survey.md](survey.md) |
| Roadmap (правила ведения `roadmap.md`) | [roadmap.md](roadmap.md) |
| Проектная память (правила ведения `PROJECT_MEMORY.md`) | [project-memory.md](project-memory.md) |
| Риски (реестр, оценка, top-10) | [risks.md](risks.md) |

## Как использовать агенту

1. **Начало проекта**: `sdlc.md` (определить фазу) → `discovery.md` (если проблема
   не валидирована) → создать `roadmap.md` и `PROJECT_MEMORY.md` (шаблоны в
   соответствующих записях).
2. **Сбор требований**: `requirements.md` + `survey.md` (интервью/опрос) →
   приоритизация MoSCoW → roadmap.
3. **В работе**: обновлять `roadmap.md` при каждом смене статуса задачи и
   `PROJECT_MEMORY.md` при каждом решении (день решения).
4. **Каждый гейт фазы**: пересмотреть риски (`risks.md`), проверить
   критерии выхода фазы (`sdlc.md`).

Конфликты: решение стейкхолдера важнее правила; решение, принятое позже,
важнее принятого раньше (обновлять `PROJECT_MEMORY.md`).
