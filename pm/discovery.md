# Discovery (фаза 0 SDLC)

**Когда использовать** — до любой разработки: новый продукт, новая фича, новый рынок.
**Когда НЕ использовать** — задача с явно валидированным запросом (например,
«исправьте этот баг» — discovery уже прошёл в виде отчёта о баге).

## Цель

**Problem-Solution Fit**: доказать, что проблема реальна, важна и часта —
до вложения в решение. Discovery отвечает на вопрос «стоит ли делать?»,
а не «что делать?».

## Последовательность

1. **Проблематика** (формат: кто / что болит / почему сейчас / чего стоит):
   ```
   <целевой пользователь> тратит <ресурс> на <рутинная задача>,
   потому что <причина>; это стало критично, так как <триггер/контекст>.
   ```
2. **Целевой пользователь (ICP)**: 2–3 признака (роль, контекст, масштаб боли).
   Не «все», не «начальник брата».
3. **Гипотеза** (проверяемая, с порогом):
   ```
   Мы считаем, что <ICP> готовы <действие: платить/использовать/рекомендовать>,
   если <решение> даст <результат>. Проверено, если ≥ <порог> из <N> интервью
   подтверждают <критерий>.
   ```
4. **Исследование**:
   - **Интервью** ≥5 целевых пользователей (правила — в [requirements.md](requirements.md));
   - **Опрос** по шаблону ([survey.md](survey.md)) — шире, глубже;
   - **Конкуренты**: что уже решает проблему (включая «Excel и почта» —
     они и есть текущее решение);
   - **Текущее поведение**: как пользователь решает задачу СЕЙЧАС (workaround) —
     если workaround отсутствует, проблема, вероятно, не важна.
5. **Синтез**: темы (не цитаты) → подтверждение/опровержение гипотезы →
   итог в `PROJECT_MEMORY.md` (раздел «Решения»: «проблема валидирована/нет,
   почему, данные»).

## Критерий выхода из discovery

- [ ] ≥5 интервью с целевыми пользователями (не друзьями/коллегами заказчика)
- [ ] Проблема подтверждена ≥70% опрошенных как важная
- [ ] Частота: проблема возникает ≥ <порог, например раз в неделю> у ICP
- [ ] Текущий workaround описан (или доказано, что его нет — и это само по себе данные)
- [ ] Гипотеза решения записана с порогом валидации
- [ ] Итог записан в `PROJECT_MEMORY.md`, scope — в `roadmap.md` (фаза 1)

## Вопросы для интервью (ядро)

1. Расскажите, как вы решаете задачу <X> сегодня? (поведение, не мнение)
2. Как часто? Последнее происхождение — когда?
3. Что плохого в текущем способе? Чего это стоит (время/деньги/нервы)?
4. Что вы пробовали изменить? Почему не помогло?
5. Как поймёте, что проблема решена? (критерий успеха пользователя)

## Питфолы

- **Solution-first**: начинать с «какую фичу сделать» и искать подтверждения.
  Discovery — про проблему; фичи — фаза 1–2.
- **Наводящие вопросы**: «вы бы воспользовались, если бы…?» → восторженный
  ответ. Спрашивать поведение и факты, не намерения.
- **Интервью с «неправильными» людьми**: стейкхолдер ≠ пользователь;
  заказчик ≠ ICP. «Мне нужно» заказчика — гипотеза, не требование.
- **Восторг = не данные**: «звучит здорово!» без изменения поведения —
  ничего не валидирует; валидируют частота, боль, workaround, готовность к действию.
- **Бесконечный discovery**: discovery — фаза с бюджетом (срок/N интервью);
  по исчерпании — решение: делать / не делать / уточнить гипотезу.
