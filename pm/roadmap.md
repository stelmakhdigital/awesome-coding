# Roadmap (`roadmap.md`) — правила

**Когда использовать** — всегда, когда есть проект на ≥1 фазу: файл `roadmap.md`
в корне целевого проекта (рядом с `PROJECT_MEMORY.md`).
**Когда НЕ использовать** — задача одного дня (достаточно задачи в трекере/коммита).

## Назначение

Единый контрольный срез проекта: **что делаем, в каком порядке, на каком этапе,
что решено**. Агент, стартующий в проекте с чистого листа, читает `roadmap.md`
(состояние) + `PROJECT_MEMORY.md` (контекст).


## Правила

1. **Задача = один проверяемый результат** (checkbox). «Сделать интеграцию» →
   «интеграция X: тесты зелёные, данные синхронизируются».
2. **Статусы**: ⬜ не начато · 🔨 в работе · ✅ готово (с датой) ·
   ⛔ заблокировано (причина + владелец + срок) · ↩️ отклонено (в «Решения»).
3. **Обновление**: при смене статуса задачи — сразу; «Обновлено» в шапке —
   всегда; фазы открываются/закрываются явно (гейты из [sdlc.md](sdlc.md)).
4. **Горизонт**: текущая фаза + следующая. Дальше — строкой-гипотезой,
   не разбитое на задачи (иначе roadmap лжёт о сроках).
5. **Scope change** — только через «Решения» (change control, см. [pmbok.md](pmbok.md));
   задача, появившаяся без решения, — scope creep, её надо легализовать или удалить.
6. **⛔ не висит бездате**: блок без владельца и срока — скрытый срыв вехи.
7. **Won't — обязателен**: без явного «не делаем» границы scope отсутствуют.
8. **Трассировка**: Must-задача → user story/NFR → источник (интервью/опрос/аналитика).

## Питфолы

- **Roadmap как список желаний**: 100 задач без фаз и вех — не roadmap.
- **Вечный 🔨**: задача «в работе» месяц — она либо заблокирована (⛔),
  либо слишком большая (разбить).
- **Дата в имени задачи** («MVP-2026-10-01»): дата слетает, имя врёт.
  Дата — в статусе, не в имени.
- **Обновление «раз в спринт»**: срез старше недели бесполезен для агента.
