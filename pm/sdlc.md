# SDLC — фазы жизненного цикла

**Когда использовать** — начало любого проекта и контроль «на какой фазе мы».
**Когда НЕ использовать** — hotfix в проде (там только «фикс + регрессия + инцидент-ревью»).

## Фазы (по умолчанию, начиная с discovery)

| # | Фаза | Вопрос фазы | Ключевые артефакты | Критерий выхода (гейт) |
|---|---|---|---|---|
| 0 | **Discovery** | Реальна ли проблема? Важна ли? | проблематика, гипотезы, итоги интервью, `PROJECT_MEMORY.md` (раздел «Проект») | ≥5 интервью подтверждают проблему; записана гипотеза решения |
| 1 | **Definition** | Что именно делаем и зачем? | `roadmap.md` (фазы + задачи), требования (MoSCoW), NFR, scope out | каждый Must-пункт — user story + acceptance criteria; стейкхолдер подтвердил scope |
| 2 | **Design** | Как это устроено? | архитектура (ADR, схемы), API-контракты, UX-макеты | ADR по ключевым решениям; дизайн ревью пройден |
| 3 | **Development** | Работает ли? | код + тесты, обновлённый `roadmap.md` | задачи ✅, CI зелёный, Definition of Done по каждому инкременту |
| 4 | **Testing** | Надёжно ли? | отчёт о тестировании, список багов | критические/мажорные баги = 0; покрытие NFR (производительность, безопасность) |
| 5 | **Release** | Доставлено ли? | релиз-ноуты, план отката, мониторинг | релиз по чек-листу; план отката проверен |
| 6 | **Operation & Feedback** | Работает ли у пользователей? | метрики, обратная связь, бэклог | метрики фазы 0-1 сверены с реальностью → новый discovery (цикл) |

## Правила

1. **Не пропускать фазу 0**: «стали кодить, потому что все знают, что нужно» —
   главный антипаттерн. Гейт фазы 0 — самый дешёвый способ не строить лишнего.
2. **Фаза ≠ длительность**: у микро-фичи фазы 2–5 занимают час; у продукта — месяцы.
   Гейты — обязательны, длительность — эластична.
3. **Итерации внутри фазы**: фаза 3 делится на спринты/итерации по 1–2 недели;
   каждая итерация — демонстрабельный инкремент (не «внутренний прогресс»).
4. **Waterfall vs Agile**: выбор по риску. Высокая неопределённость (новый рынок,
   новая технология) → короткие фазы + ранние итерации; стабильное доменное
   требование с жёстким дедлайном → жёсткие гейты, меньше итераций.
5. **Изменение scope на любой фазе** — через change control (см. [pmbok.md](pmbok.md)):
   решение → `roadmap.md` (раздел «Решения») + `PROJECT_MEMORY.md`.
6. **Фаза = блок в roadmap.md**: фаза открывается (🔨) и закрывается (✅)
   явно; «вечные» фазы — признак потери контроля.

## Питфолы

- **Discovery «для галочки»**: 2 интервью с друзьями → «все согласны».
  Интервью — с целевым пользователем (см. [discovery.md](discovery.md)).
- **Scope creep в фазе 3**: новые «маленькие» требования без change control —
   фактический перенос релиза.
- **Тестирование «в конце»**: баги из фазы 3 обнаруживаются в фазе 4 —
   переделка в 5–10 раз дороже. CI + тесты — с первой итерации.
- **Release без плана отката**: «откатимся к прошлому деплою» не считается планом,
  если миграции данных односторонние.
- **Конец фазы 6 не замечен**: проект «закрыт», а метрики не собраны —
  discovery следующего цикла стартует без данных.
