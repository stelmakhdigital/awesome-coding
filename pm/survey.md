# Опрос для сбора требований

**Когда использовать** — количественная часть discovery: частота проблемы,
приоритеты, сегментация. Глубину даёт интервью (см. [discovery.md](discovery.md));
опрос — масштаб и цифры.
**Когда НЕ использовать** — как единственный метод (без интервью/аналитики) —
опрос не отвечает «почему».

## Правила

1. **5–10 вопросов, ≤ 5 минут**: длиннее — падает доведение до конца.
2. **Сначала открытые** (поведение), потом закрытые (шкалы/выбор).
3. **Без наводящих**: «Насколько удобно вам…?» → «Расскажите, как вы…?».
4. **Одна переменная на вопрос**: «быстро и удобно?» — два вопроса.
5. **Скрининг первым**: отсечь не-ICP («Занимаетесь ли вы <деятельностью>?» →
   нет → опрос завершён).
6. **Контекст в начале**: кто мы, зачем опрос, сколько времени — повышает честность.
7. **Не стимулировать «правильные» ответы**: без призов за конкретные ответы;
   призыв «расскажите, как есть» лучше «что вам важно?».

## Шаблон (адаптировать под проект)

```markdown
# Опрос: <проблема> (3–5 минут)

Мы изучаем, как <деятельность>, чтобы улучшить <что>. Отвечайте, как есть —
оценок «правильного ответа» нет.

## Скрининг
1. Какую роль/задачу вы выполняете, связанную с <область>?
   [текст] → (не соответствует ICP: опрос завершён, спасибо)

## Текущее поведение
2. Как вы решаете задачу <X> сейчас? Пошагово. [текст]
3. Как часто это происходит? (ежедневно / несколько раз в неделю / реже)
4. Что вы пробовали, чтобы сделать это лучше? [текст + выбор: ничего /
   ручной workaround / инструмент (какой?)]

## Боль
5. Что в текущем способе хуже всего? [текст]
6. Чего это стоит (время в неделю / деньги / другие потери)?
   [слайдер 0–10: насколько это мешает вам работать]

## Решение (гипотеза)
7. Какой результат для вас будет означать «проблема решена»? [текст]
8. Что в таком решении было бы обязательным / лишним? [текст]
9. Если бы такое решение существовало, вы…? (порекомендовали бы коллегам /
   попробовали / посмотрели бы)

## Контакты
10. Можно ли вернуться с уточняющими вопросами? (имя/контакт, добровольно)
```

## Анализ результатов

1. **Количественное**: частота проблемы (вq3), интенсивность боли (в6),
   готовность (в9) — по сегментам (в1).
2. **Качественное**: открытые ответы → темы (кодовка: каждый ответ → 1–3 темы),
   топ-5 тем с примерными цитатами.
3. **Критерий**: пороги гипотезы из discovery (например, «≥70% отмечают боль ≥7/10»).
4. **Итог** — в `PROJECT_MEMORY.md` (раздел «Решения»: дата, N ответов, ключевые
   цифры, подтверждена/опровергнута гипотеза).

## Питфолы

- **Самовыборка**: отвечают те, у кого сильное мнение (в обе стороны);
   сравнить структуру ответов с аналитикой, если она есть.
- **Вопрос-утверждение**: «Согласны ли вы, что это важно?» — все соглашаются.
- **Один опрос на всё**: опрос проверяет конкретную гипотезу — разная гипотеза,
   разные вопросы 7–8.
- **Результат без интерпретации**: «42% ответили „да“» — не вывод;
   вывод — «гипотеза X подтверждена для сегмента Y при пороге Z».
