# Агентские автоматизации

Версии инструментов: **bash 5.3** (flock, `timeout`, `setsid`), **gh 2.x**, **git 2.5x** с worktree. Закреплено на 2026-11-24. Оркестратор специально не закреплён: CLI агентов меняется быстрее, чем правила ниже, — привязывать раздел к конкретному инструменту значит обесценить его через полгода.

> Здесь про прогоны, в которых агент делает работу без человека в цикле: охотник за багами по диффу, ночная сверка версий, разбор отчётов, координатор с воркерами. Отличия от «просто скрипта» три: вход недетерминирован (модель), вывод надо проверить, а цена ошибки — не упавший job, а испорченная ветка или спам в трекере.

## Конвенции

- У прогона есть код возврата и лог, которые переживают прогон: «в консоли было красиво» не считается.
- Вход прогона фиксируется: sha коммита, id задачи, дата. Повтор того же входа не должен производить второй вывод.
- Вывод прогона — в трекер или PR, а не в stdout: stdout забывается через час, трекер видит следующий человек и следующий прогон.
- У вывода есть потолок (число задач, строк, строк кода). Без потолка агент, которому «ещё чуть-чуть», приносит 40 находок и половину из них выдумывает.
- Каждый вывод содержит доказательство: файл:строка, команду воспроизведения, ссылку на упавший тест.
- Права прогона — минимальные: токен с `contents: read` там, где чтение; запись только там, где создаётся issue.
- Опасные действия (push в защищённую ветку, merge, миграция, удаление) — вне полномочий прогона, только через человека.

## Инструменты

`bash -n`, `shellcheck` (в прогоне раздел проверяется им же: `make verify`), `flock`, `timeout`, `setsid`, `git worktree`, `gh` (`--json`/`--jq`, `--search`), `systemd` timers, GitHub Actions `schedule`.
