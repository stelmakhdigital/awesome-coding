# Агентские автоматизации: таблицы решений

## Где запускать

| Площадка | Задержки | Секреты | Лог | Когда брать |
|---|---|---|---|---|
| `systemd` timer | `Persistent=true` догоняет пропущенные запуски после простоя | в unit-файле/`EnvironmentFile`, вне репозитория | `journalctl -u` | задача на своей машине, где уже есть рабочий каталог и инструменты |
| `cron` | без догоняющих запусков; `@daily` гуляет вместе с переводом часов | в окружении или в файле с правами 600 | письмо/перенаправление, то есть обычно никто | переносимость между машинами важнее удобства |
| GitHub Actions `schedule` | сдвиги при нагрузке на раннеры; workflow с репозиторием без коммитов 60 дней не запускается вовсе | секреты репозитория, `GITHUB_TOKEN` по скоупу | артефакт, виден по ссылке | задача про репозиторий, вывод — issue/PR, человек смотрит в GitHub |
| Хук (post-receive, `post-merge`, webhook) | нет задержки | те же, что у площадки | вывод хука почти всегда теряется | реакция на событие, а не расписание |
| Автоматизация оркестратора (очередь задач, свой планировщик) | как настроено | как настроено | внутри инструмента | несколько связанных прогонов, им нужен общий стейт и дедупликация |

Правило выбора одно: площадка обязана отвечать на «почему прогон не запустился». Если после трёх дней тишины нельзя отличить «нечего делать» от «планировщик умер» — площадка не подходит, нужен хотя бы heartbeat.

## Где держать состояние прогона

| Что помним | Где | Чем плохо альтернативное |
|---|---|---|
| «до какого коммита обработано» | поле в теле issue/задачи или `.agent-state/` в репозитории | журнал в домашнем каталоге живёт на одной машине и не виден следующему прогону с другого раннера |
| «это уже найдено» | поиск по трекеру + метка прогона | помнить список в памяти прогона — значит плодить дубли при каждом пересоздании |
| «прогон жив» | timestamp-файл или метрика heartbeat | молчание не отличимо от смерти |
| «результат прошлого раза» | артефакт/файл в рабочем каталоге + sha входа | полагаться на stdout: его никто не читает после завершения |
| «что уже отправлено наверх» | PR/комментарий с идентификатором входа | коммиты от агента без ссылки на вход не сопоставимы с задачей |

Хранить надо ответ на вопрос, который задаст следующий прогон. Всё остальное — балласт, который обязательно разъедется с реальностью.

## Куда выводить

| Форма | Когда | Обязательное условие |
|---|---|---|
| Задача в трекере | дефект, требующий решения позже | дедупликация перед созданием; доказательство в теле |
| Pull request | прогон что-то починил и это надо посмотреть до слияния | своя ветвь, зелёный CI, человек на слиянии |
| Комментарий к существующей задаче | то же явление замечено второй раз | не создавать новую задачу «о том же» |
| Файл/отчёт в репозитории | регулярная сверка (версии, просрочки, покрытие тестами) | отчёт должен меняться только когда изменилась правда |
| Уведомление в чат | дежурному нужно действие сейчас | порог: тишина допустима, «всё хорошо» каждый день — нет |

## Один агент или несколько

| Сигнал | Решение |
|---|---|
| Работа укладывается в бюджет одного прогона | один агент, одна ветка |
| Этапы имеют разную цену (поиск дешёвый, правка дорогая) | конвейер: сначала фильтр, дорогая модель только на отобранных пунктах |
| Подзадачи не зависят друг от друга | параллельные воркеры, каждому свой worktree ([patterns/coordinator-workers.md](patterns/coordinator-workers.md)) |
| Подзадачи трогают одни и те же файлы | последовательно: два агента в одном дереве = конфликт и взаимные откаты |
| Результат надо проверить до продолжения | gate: отдельный проверяющий, а не «тот же агент, но внимательно» |
| Нужна история решений | состояние прогона вне контекста агента: контекст заканчивается, файл — нет |

## Что агенту разрешено

| Действие | Разрешить | Граница |
|---|---|---|
| Читать репозиторий, логи, трекер | да | токен только на чтение |
| Править рабочий каталог прогона | да | отдельные ветвь и worktree |
| Создавать задачу | да | с меткой прогона и доказательством |
| Создавать PR | да | в own ветвь, никогда в защищённую |
| Сливать PR, тегать, релизить | нет | человек или зелёный CI + человек |
| Писать в прод, менять схему, выкатывать | нет | вне полномочий автоматизации |
| Менять секреты, права, настройки площадки | нет | вне полномочий автоматизации |
| Запускать чужой код из репозитория | осмотрительно | изолированное окружение, лимиты ([../go/snippets/proxy.md](../go/snippets/proxy.md) про границы времени) |

## Какую модель на какой этап

| Место конвейера | Качество ответа | Комментарий |
|---|---|---|
| Разбор входа, категоризация, фильтрация | слабая/дешёвая модель | ошибки здесь фильтруются следующими шагами |
| Правка кода | средняя | правки, оставшиеся без ревью, дороже экономии |
| Проверка чужой работы | самая сильная из доступных | проверяющий на слабой модели превращается в второго автора |
| Финальный отчёт человеку | средняя | формат важнее глубины |

Проверка модели на фактах, а не по ощущениям — [../llm/evals.md](../llm/evals.md).
