# Координатор и воркеры в отдельных worktree

Один агент делит работу на независимые куски, раздаёт её воркерам — каждый в своём `git worktree` и своей ветке, — а потом сводит результаты через проверяемый gate.

**Когда использовать** — работа разлагается на подзадачи, которые не трогают одни и те же файлы: прогнать миграции по нескольким сервисам, обновить одинаковые вызовы API в десяти модулях, починить найденные охотником дефекты пачкой, перевести разделы на новый API. Время последовательного выполнения — за пределами терпения (час и больше).
Когда не брать: подзадачи пересекаются по файлам (двое в одном дереве — взаимные откаты и неразрешимые конфликты); задача маленькая (накладные расходы на координацию дороже экономии); результат требует одного автора (проектирование интерфейса — не параллелится).

## Форма

```text
repo (master)
├── worktrees/task-01  →  branch agent/task-01  →  worker-01
├── worktrees/task-02  →  branch agent/task-02  →  worker-02
└── worktrees/task-03  →  branch agent/task-03  →  worker-03
          ↑
     координатор: раздача, приёмка, слияние по одному
```

```bash
#!/usr/bin/env bash
# shellcheck shell=bash
# worker-tree.sh — изолированное рабочее пространство воркера.
set -euo pipefail

ROOT="${ROOT:-$(pwd)}"
BASE="${BASE:-origin/master}"

# worker_prepare <id> — чистая worktree от актуальной базы. --detach внутри не
# нужен: воркеру нужна своя ветвь, а не «голый» коммит.
worker_prepare() {
  local id="$1"
  local dir="$ROOT/worktrees/$id"
  if git -C "$ROOT" rev-parse --verify --quiet "agent/$id" >/dev/null; then
    git -C "$ROOT" worktree add "$dir" "agent/$id"
    return 0
  fi
  git -C "$ROOT" worktree add -b "agent/$id" "$dir" "$BASE"
}

# worker_finish <id> — убрать worktree, ветвь остаётся до слияния.
worker_finish() {
  local id="$1"
  git -C "$ROOT" worktree remove --force "$ROOT/worktrees/$id"
  git -C "$ROOT" branch -D "agent/$id"   # только после принятого слияния
}
```

## Контракт воркера

Воркер обязуется сделать четыре вещи; координатор проверяет ровно их:

1. **Только своя область.** Список файлов или директорий в задании — граница. Правка «попутно» вне неё — отклонённая работа, а не любезность.
2. **Собранный проект.** Тесты и линтер в своей worktree проходят; вывод прикладывается, а не утверждается («всё зелёное» без лога — не вывод).
3. **Один коммит — одна забота** ([../../shared/commits.md](../../shared/commits.md)), сообщение по формату проекта.
4. **Тишина про чужое.** Найденный попутный дефект — в отчёт текстом, не в дифф.

Координатор не принимает на веру: сборка и тесты прогоняются в его окружении, а в ветке воркера смотрят на дифф, а не на описание.

## Порядок слияния

| Шаг | Зачем |
|---|---|
| Слияние по одному, с прогоном тестов после каждого | два «зелёных по отдельности» диффа дают красное дерево; винить в этом надо конкретный шаг |
| Конфликт — возврат воркеру, а не ручная правка координатором | человек в конфликте двух агентских диффов принимает решение вслепую |
| Никаких `merge` в защищённую ветку из автоматизации | слияние — точка, где нужна ответственность |
| Worktree убирается после принятого слияния | осевшие worktree — это «а где та ветка была?» через месяц |

## Типовые отказы

| Отказ | Причина | Профилактика |
|---|---|---|
| Воркеры поправляют одно место по-разному | граница задана задачей, а не файлами | область = список путей; пересечение — последовательно |
| Каждый воркер принёс «свой» стиль сборки | окружение не описано | единая команда проверки в задании, один и тот же образ |
| Дерево master уехало вперёд, ветки отстают | `BASE` взят из локального `master` без fetch | база — `origin/master` после `fetch`; перебаза до приёмки |
| Координатор «решил, что готово» и слил | приёмка на словах | gate: прогон тестов + дифф перед глазами, у человека или в CI |
| worktree остались после падения прогона | нет cleanup | `git worktree prune` в начале прогона, `worker_finish` в ловушке |
