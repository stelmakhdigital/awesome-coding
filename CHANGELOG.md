## v1.8 — 2026-11-25

Две темы, где цена ошибки — не упавший тест: исполнение чужого кода и две СУБД
в одном коде.

### Содержимое

- `arch-code-sandbox` — песочница для кода, который принёс пользователь: контракт
  прогона (время, память, pid, сеть, файлы, потолок вывода, отдельный код за
  таймаут, 503 при недоступном изоляторе), набор флагов запуска с причиной у
  каждого, убийство контейнера по cid вместо убийства клиента `docker run`,
  что runc не закрывает (смонтированный docker.sock — root хоста, одно ядро на
  всех, `--user` = ваш uid), языки и их лимиты, три теста без которых изоляция —
  это флаги после обновления.
- `database-dialect-portability` — SQLite в тестах и PostgreSQL в проде: таблица
  расхождений (внешние ключи по умолчанию выключены, affinity, `IS DISTINCT FROM`,
  регулярки, `ALTER TABLE`, `SQLITE_BUSY`, регистронезависимый `LIKE`), запросы по
  диалекту вместо подстановки плейсхолдеров, прагмы в DSN, тест на паритет.

### Цифры

194 записи. Проверено прогоном: 147 блоков собрано и выполнено, 4 — `deps`,
9 — фрагменты.

Агентам нужен перекэш: пин поднят до v1.8.

## v1.7 — 2026-11-25

Раздел `agenting/`: автоматизации, в которых агент работает без человека в цикле.

### Содержимое

- 8 записей: правила (повторяемость, бюджет, доказательства, полномочия,
  наблюдаемость, эскалация), таблица решений (площадка запуска, где держать
  состояние, форма вывода, один агент или DAG, что разрешено агенту, какую
  модель на какой этап), три сниппета и три паттерна.
- `agenting-lockfile` — единовременный прогон на `flock` с self-test'ом;
  `agenting-watchdog` — бюджет времени, убийство группы процессов, потолок
  вывода; `agenting-run-state` — чекпоинт прогона и дедупликация вывода по
  метке в теле задачи.
- Паттерны: охотник за дефектами по диффу (правила поиска, потолок находок,
  тело задачи с доказательством, метрики полезности), координатор и воркеры в
  отдельных worktree, спецификация как контракт с исполняемыми критериями
  приёмки.
- Оркестратор не закреплён намеренно: CLI агентов меняется быстрее правил.

### Туллинг

- Секция и язык `agenting` зарегистрированы в валидаторе, `index/agenting.yaml`,
  `docs/FORMAT.md`; маршрут в `AGENTS.md` и `SKILL.md` — по признаку расписания
  с агентом внутри.

### Цифры

192 записи, 18 разделов. Проверено прогоном: 144 блока собрано и выполнено,
4 — `deps`, 9 — фрагменты.

Агентам нужен перекэш: пин поднят до v1.7.

  `FlushInterval` для потоков, `MaxBytesReader` до разбора, перенос отмены в

## v1.1 — 2026-11-24

Тулчейк проверки кода, раздел `llm/`, недостающие guardrails; `verified` — по факту прогона.

### Туллинг

- `tools/verify_snippets.py` + `make verify` / `make verify-fix` — код-блоки записей
  прогоняются реальными тулчейнами в Docker (go build+vet, tsc --strict, Python 3.14

  прогона и никогда не понижается. В CI — отдельный job по языкам.
- `tools/ac.py` — общий разбор формата (frontmatter, каталог, код-блоки): валидатор,
  поиск, audit и верификатор читают формат из одного места.
- `tools/readme.py` — блок «Статус разделов» генерируется из каталога
  (`make readme`; в `make validate` — проверка, что блок не разошёлся).

- `tools/mcp_server.py` — MCP-сервер поверх каталога: `search` идёт по каталогу,

- Раздел `llm/` — приложения с моделью: правила (таймаут, ретраи, бюджет, версия
  промпта, путь деградации, что писать в логи), таблицы решений, `evals.md` и два
  сниппета одного слоя вызова (Go на stdlib, Python на httpx).
- `messaging/rules.md` — доставка и дедупликация, DLQ и backoff, порядок сообщений,

- `go/snippets/rate-limit.md` — token bucket на ключ с eviction, 429 с Retry-After,

- `architecture/patterns/layered.md` — добавлен пакет `domain`, запись собирается целиком.
