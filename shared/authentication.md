# Аутентификация — принципы

**Когда использовать** — любой вход в систему: логин, API-токен, OAuth, сброс пароля.
**Когда НЕ использовать** — авторизация (кто что имеет право делать): это отдельный
слой, `authentication.md` его не покрывает; рядом — [security.md](security.md).

## Принципы

1. **Пароли — только хеш с памятью-жёсткостью**: argon2id (фолбэк bcrypt/scrypt).
   Каждый новый хеш — со свежей солью; параметры проверяются и тихо апгрейдятся
   при входе, а не мигрируются батчем.
2. **Сессия против токена — это выбор отзыва, а не моды.** Серверная сессия
   отзывается мгновенно; JWT — нет, поэтому короткая жизнь access-токена
   (5-15 минут) + refresh с ротацией.
3. **Алгоритм проверяется явно.** Проверяющая сторона держит список разрешённых
   алгоритмов и отклоняет всё остальное (включая `alg: none`); `iss`, `aud`, `exp`,
   `nbf` проверяются всегда, перекос часов — не больше минуты.
4. **Внешний вид входа не должен ничего сообщать.** Ошибка одна и та же для
   «нет такого пользователя» и «неверный пароль», время ответа сопоставимое.
5. **Темп входа ограничен** — по аккаунту и по источнику, с backoff; без этого
   перебором с параллелизмом перебирают любой слабый пароль.
6. **MFA проверяется на месте, а не «один раз при входе»**: смена пароля, выплата,
   удаление — повторное подтверждение.
7. **Ссылка «войти по письму» и OAuth `redirect_uri` — точное совпадение
   из списка.** Префиксное совпадение = открытый редирект = украденный код.
8. **Что не должно попадать никуда**: пароли, токены, refresh-токены — в логи,
   в URL (они оседают в прокси и истории), в `localStorage` (XSS забирает мгновенно).

## ✅ / ❌

- ✅ `argon2id`, параметры из конфигурации; ❌ `md5`, `sha1`, «голый» `sha256`, «сам
  сделал соль из имени»
- ✅ Хеш пароля хранится как строка с параметрами (`$argon2id$v=19$m=65536,t=3,p=4$…`)
  и переустановкой по месту; ❌ отдельная колонка «алгоритм» + своя логика миграции
- ✅ Cookie-сессия: `HttpOnly`, `Secure`, `SameSite=Lax` (+ `Strict`, если уместно);
  ❌ `localStorage` для токена как основной способ хранения
- ✅ Проверяем `alg` из белого списка (`RS256`/`ES256`/`EdDSA`), ключи по `kid` из JWKS
  с кэшем и обновлением на неизвестный `kid`; ❌ «раскодируем что принесли»
- ✅ Refresh-токен одноразовый: использовали — выдали новый, повторное использование
  старой версии = отзыв всей цепочки (защита от украденного refresh)
- ✅ OAuth: `state` + PKCE для публичных клиентов; ❌ `response_type=token` в браузере
  и implicit-поток в новом коде
- ✅ `crypto.timingSafeEqual` / `hmac.compare_digest` / `MessageDigest.isEqual` для
  сравнения секретов; ❌ `==` на токенах и подписях (и по времени, и по содержанию)
- ✅ Ошибка входа одна: «неверные учётные данные»; ❌ «пользователь не найден» и
  «пароль неверный» — это справочник для перебора
- ✅ Ссылка сброса: одноразовая, хранится хешем, живёт минуты, отзывается после
  использования; ❌ «отправили письмо, если такой e-mail есть» в ответе с любым
  различимым поведением
- ✅ Смена пароля/подозрительная активность — отзыв всех сессий и уведомление;
  ❌ «поменяли пароль, старые токены живут до истечения»
- ✅ TOTP: допуск ±1 шаг, лимит попыток, одноразовые коды восстановления (тоже хешем);
  ❌ секрет TOTP в открытом виде в профиле
- ✅ WebAuthn/passkey — основной второй фактор там, где возможно: нет фишинга
  и нет «перехвата SMS»
- ✅ Авторизация перепроверяется на каждом запросе (`WHERE id = $1 AND owner_id = $2`);
  ❌ «раз токен валиден — доступ разрешён» (IDOR — самый частый баг после правильного JWT)

## Библиотеки (не рекомендации «единственные», а то, что не надо писать самому)

| Язык | Пароли | JWT/куки-сессии |
|---|---|---|
| Go | `golang.org/x/crypto/argon2` | `github.com/golang-jwt/jwt/v5` (с явным `WithValidMethods`) |
| Python | `argon2-cffi` | `pyjwt` (`algorithms=[…]`) или `authlib` |
| TypeScript | `@node-rs/argon2` | `jose` (JWT), `lucia`/`oslo` (сессии) |
| C# | `BCrypt.Net-Next` / ASP.NET Identity | встроенная Identity + Data Protection |
| Kotlin | `spring-security-crypto` (`Argon2PasswordEncoder`) | Spring Security |

Сессионное хранилище — Redis (см. [../database/snippets/redis.md](../database/snippets/redis.md)),
а не «в памяти процесса»: два пода с разными представлениями о входе — это баг.

## Pitfalls

- Проверка `exp` своими руками через сравнение с `time.Now()`: забывайте `nbf`, `iat`,
  скос — используйте библиотеку и её опции.
- JWKS без кэша: каждый запрос — HTTP к провайдеру (и деградация при его недоступности);
  с кэшем «навсегда» — отозванный ключ продолжает работать.
- Access-токен на часы «чтобы не дёргать refresh»: отзыв превращается в ожидание.
- Разрешить `alg` из заголовка — классическая подмена токена (RS256 → HS256 с публичным ключом).
- Мера «один вход — один IP»: VPN и мобильная сеть ломают её в первый же день;
  ограничивайте частоту, а не факт смены IP.
