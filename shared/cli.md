# CLI — правила

**Когда использовать** — написание/использование консольных инструментов (утилиты, миграции, админ-команды, агенты).
**Когда НЕ использовать** — интерактивные TUI-приложения (там другие правила); скрипты «на один раз» (но и там — exit codes).

## Принципы (Unix)

1. **Одна задача** — инструмент делает одно и делает хорошо; составление — через пайпы.
2. **Данные — stdin/stdout, диагностика — stderr**: вывод, пригодный для пайпа, не смешивать с логами.
3. **Предсказуемость**: один и тот же ввод → один и тот же вывод (идемпотентность по умолчанию).
4. **Не интерактивный по умолчанию**: флаги/аргументы вместо промптов; интерактив — только явный режим (`--interactive`) или TTY-обнаружение.

## Флаги и аргументы

✅

- `--help` и `--version` — обязательны; `--help` — человекочитаемый, без ошибок.
- Длинные флаги — самоописывающиеся: `--output-dir`, не `-od`; короткие — только для частых (`-v`, `-o`).
- Позиционные аргументы — для «главных» объектов (`tool <input> [output]`); остальное — флаги.
- Негативные флаги — осторожно (`--no-color` ок, `--not-verbose` — нет): предпочитайте `--color=auto|always|never`.
- Значения по умолчанию — разумные и задокументированные; «молчание» ≠ «не задано» (различайте `--flag` и `--flag=value`).
- Валидация на старте: все ошибки аргументов — до начала работы, с понятным сообщением.

❌

- Промпты в середине работы (потеря контекста, нескриптуемость).
- Магическое поведение по окружению без флага (кроме устоявшихся: `NO_COLOR`, `CI`, `TERM`).
- Секреты в аргументах (видны в `ps`/истории) — env-переменные или stdin.

## Exit codes и вывод

✅

- `0` — успех; `1` — общая ошибка; разные коды — для разных классов (документируйте в `--help`).
- Ошибка — однострочное сообщение на stderr: `tool: причина (подсказка)`.
- Машины: `--json` (стабильная схема) — отдельный режим, не «иногда JSON».
- Прогресс — только на TTY (в пайп/файл — не писать); `--quiet`/`--verbose` — уровни.

## Скриптуемость

- Вывод по умолчанию — без украшений (цвет только на TTY, `NO_COLOR` уважается).
- Путь к файлам — абсолютные/как заданы, без «красивого» сокращения.
- Таймауты и отмена: `SIGINT`/`SIGTERM` — корректное завершение (cleanup, частичные файлы — не оставлять).
- Идемпотентность: повторный запуск с теми же аргументами — тот же результат, без дублей.

## Pitfalls

- **stdout засорён логами** — пайп получает мусор; диагностика — только на stderr.
- **Exit code 0 при ошибке** («но что-то же напечатал») — скрипты-обёртки не видят сбой.
- **Интерактивный промпт в CI** — висящий джоб; `CI=true` → без интерактива.
- **Разный вывод в разных версиях** без заметки — ломаются скрипты пользователей.
