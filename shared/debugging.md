# Debugging — методология

**Когда использовать** — любой баг: свой, чужой, воспроизводимый или «иногда падает».
**Когда НЕ использовать** — «баг» на самом деле фича/непонятная спецификация: сначала уточните ожидаемое поведение.

## Порядок (не пропускать шаги)

1. **Воспроизвести** — стабильный минимальный воспроизводитель. Не воспроизвели — ищете условия (данные, окружение, порядок, тайминги).
2. **Минимизировать** — уберите всё лишнее из воспроизводителя: данные, зависимости, шаги.
3. **Локализовать** — бисекция: по коду (`git bisect`), по данным (половинный поиск), по времени (когда началось — `git log`/деплой).
4. **Гипотеза → проверка** — одна гипотеза за раз; проверка = изменение, которое подтвердит/опровергнет.
5. **Фикс + регрессионный тест** — тест, который падал до фикса и проходит после. Без него баг вернётся.
6. **Корневая причина** — починили симптом? Задайте «почему?» до причины (5 why), иначе появятся «родственные» баги.

## Правила

✅

- Логи/вывод **до** фикса — сохранить (они же — материал для регрессионного теста).
- `git bisect run <скрипт>` — автоматическая бисекция: 20 коммитов за 5 итераций.
- Разница «работает/не работает» — ваш главный инструмент: сравните окружения, версии, данные.
- Печатайте/логгируйте на границах подозрительной функции: входы, выходы, условия.
- «Иногда падает» — ищите race (лог с таймингами, `-race`/sanitizers), зависимости от порядка, кэши.

❌

- Не чините «наугад» и не коммитьте эксперименты в общую историю (ветка/stash).
- Не удаляйте «проблемный» код, не понимая, почему он срабатывает.
- Не доверяйте первому объяснению: «просто перезапустил» — не фикс.
- Не отлаживайте в проде, если можно воспроизвести локально (prod — только чтение логов).

## Инструменты по ситуации

| Ситуация | Инструмент |
|---|---|
| Баг появился в N последних коммитах | `git bisect` |
| Гонка/падение в памяти | race detector, ASan/UBSan, valgrind |
| Медленно | профилировщик (CPU/heap), не «по ощущениям» |
| Ошибка в данных | минимальный набор данных + дамп на границе |
| «У меня работает» | diff окружений: версии, env, конфигурация, права |

## Pitfalls

- **Heisenbug**: баг исчезает при наблюдении — признак race/таймингов; не «починили», а нашли условие.
- **Лечение симптома**: заглушка (retry, sleep, hardcode) без причины — временный фикс, маркер `TODO(root-cause)`.
- **Отладка по памяти**: «я же помню, что там было» — читайте фактический код и логи.
- **Огромный воспроизводитель**: если воспроизводитель на 1000 строк — минимизация не сделана.
