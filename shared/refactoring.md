# Refactoring — правила

**Когда использовать** — изменение структуры кода без изменения поведения: выносы, переименования, упрощение, устранение дублирования.
**Когда НЕ использовать** — добавление нового поведения (это фича, не рефакторинг); «рефакторинг» целой кодовой базы за одну сессию.

## Порядок

1. **Тесты до рефакторинга**: покрывают ли существующие тесты поведение? Нет — сначала допишите characterization-тесты (фиксируют текущее поведение, даже странное).
2. **Маленькие шаги**: один рефакторинг-шаг = одна правка + зелёные проверки. Не «и переименовать, и вынести, и переписать».
3. **Компилятор/типы/линтер — союзники**: переименования и переносы — инструментами (IDE, `gofmt -r`, `sed` по паттерну), не руками.
4. **После каждого шага**: тесты + линтеры + сборка. Красный — откатить шаг, искать причину.
5. **Отдельный коммит** на логический блок (см. [commits.md](commits.md)): рефакторинг не смешивается с фичами и фиксами.

## Правила

✅

- Сначала — самое безопасное: переименования, вынос констант, упрощение условий.
- Дублирование → общий код только после понимания, что дублируется **поведение**, а не текст.
- Мёртвый код удаляется (проверьте ссылки/рефлексию/сериализацию перед удалением).
- Глубокие вложенности → early return; длинные функции → вынос с осмысленным именем.
- Магические числа/строки → именованные константы.

❌

- Не рефакторите «на лету» в коммите с новой фичей — review становится невозможным.
- Не меняйте публичный API/контракты в «тихом» рефакторинге — это breaking change, отдельное решение.
- Не оптимизируйте «по ощущениям» — только по профилю (см. [debugging.md](debugging.md), бенчмарки).
- Не рефакторите чужой код, который не понимаете, без тестов — сначала characterization.

## Критерий остановки

- Поведение не изменилось (тесты те же, зелёные).
- Код стал проще: меньше вложенности/дублирования/имён, которые нужно запомнить.
- Если после шага код не стал проще — шаг был не рефакторингом, откатите.

## Pitfalls

- **Слизь (slippery slope)**: «пока тут поправлю» → коммит на 2000 строк. Останавливайтесь на логической границе.
- **Рефакторинг без тестов** — не рефакторинг, а лотерея.
- **Имена как документация**: плохое имя до рефакторинга — повод переименовать первым шагом.
- **Массовые авто-рефакторинги** (formatter на весь репо) — отдельный коммит, только форматирование.
