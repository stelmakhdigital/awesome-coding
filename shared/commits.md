# Commits — правила для агентов

**Когда использовать** — любой коммит в git-репозиторий: свой код, рефакторинг, туллинг, документация.
**Когда НЕ использовать** — локальный scratch-веточный WIP, который не попадёт в общую историю; автокоммиты инструментов (результат коммитите сами, осознанно).

## Формат сообщения

- **Язык — русский** (или язык проекта), без conventional-префиксов (`feat:`, `fix:`).
- **Первая строка — что и зачем, ≤ 72 символа**: `Туллинг: CI, make search, mermaid-валидатор`.
  Забота в начале строки (`Туллинг:`, `Контент:`, `Процессы:`) делает `git log` читаемым.
- **Тело (опционально) — детали**: что изменено, почему, как проверено.
- **Один коммит — одна забота**: туллинг, контент и процессы — разные коммиты.

Примеры первых строк:

| Хорошо | Почему |
|---|---|
| `Туллинг: CI, make search, mermaid-валидатор` | забота + что |
| `Пять сниппетов: FastAPI, C# Options, Unity Addressables, bash curl, Go gRPC` | что + перечень |
| `Процессы: ADR (agent-first, pinned versions), mermaid-диаграмма в README` | забота + что |
| `Исправить N+1 в загрузке заказов (batch-запрос)` | проблема + как |

Плохо: `fix`, `wip`, `обновления`, `коммит 2`, `добавил фичу` — из логa не понять, что изменилось.

## Атомарность

- Один коммит — одно логическое изменение: фича, фикс, рефакторинг, обновление зависимостей.
- Не смешивайте: изменение поведения + форматирование, фикс + рефакторинг, контент + туллинг.
- Файл с изменениями разных забот — разделяется: сохранить финальную версию → вернуть HEAD →
  применить часть → коммит → применить остаток → коммит.
- Размер: diff ревьюится за один присест (ориентир ≤ ~300 строк); больше — делите по подсистемам.
- Каждый коммит осмыслен сам по себе: не ломает сборку/валидацию, к нему можно вернуться (bisect).

## Перед коммитом

- Линтеры/тесты/валидаторы — зелёные (`make validate`, проверки CI).
- `git status` — нет чужих файлов: временные, `.env`, `node_modules/`, артефакты сборки.
- Метаданные — в том же коммите, что и контент: индексы, документация, lock-файлы.
- Секретов в diff нет: ключи, токены, пароли — ни в коде, ни в сообщении.

## История

- `amend` — только для коммитов, ещё не запушенных.
- Force-push в общие ветки (master/main) — запрещён; в свою feature-ветку — допустим.
- Чужую историю не переписывайте.
- Перед рискованным рефакторингом — контрольный коммит (страховка; позже можно переписать).
- Отладочных остатков нет: `console.log`/`Debug.Log`, закомментированный код, `TODO: убрать`, временные файлы.

## Lock-файлы

- `package-lock.json`, `go.sum`, `poetry.lock`, `Cargo.lock` — **коммитите** (воспроизводимость сборки).
- `node_modules/`, `.venv/`, `target/` — **никогда** (`.gitignore`).

## Pitfalls

- **Один коммит на всё**: большой смешанный коммит нельзя ни ревьюить, ни bisect'ить.
- **Коммит «чтобы не потерять»**: WIP — в stash или личную ветку, не в общую историю.
- **Сообщение без контекста**: «fix bug» — какой баг, почему так, как проверено?
- **Молчаливое изменение контракта**: API/схема/метаданные изменились, а сообщение об этом молчит.
- **Генерация в коммите**: правки сгенерированного кода — коммитите результат и источник генерации вместе.
