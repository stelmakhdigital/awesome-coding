# CONTRIBUTING

## Добавление записи

1. Прочитайте [FORMAT.md](FORMAT.md).
2. Создайте файл в нужном каталоге: `<lang>/snippets/` или `<lang>/patterns/`.
3. Заполните frontmatter; убедитесь, что `id` уникален (проверьте `index/<section>.yaml`).
4. Добавьте запись в `index/<section>.yaml` (раздел по имени файла).
5. Проверьте: код запускается/компилируется, ссылки работают, теги осмысленны.

## Чек-лист

- [ ] Frontmatter полный, `id` уникален
- [ ] Есть «Когда использовать / Когда НЕ использовать»
- [ ] Код компилируется/запускается на закреплённой версии языка
- [ ] Есть секция Pitfalls
- [ ] `index/<section>.yaml` обновлён
- [ ] Все ссылки валидны (относительные, без битых)
- [ ] `updated` актуален

## Коммиты (для агентов и людей)

### Сообщение

- Язык — русский, без conventional-префиксов (`feat:`, `fix:`).
- Первая строка — что и зачем, ≤ 72 символа: `Туллинг: CI, make search, mermaid-валидатор`.
- Тело (опционально) — детали: что изменено, почему, как проверено.
- **Один коммит — одна забота**: туллинг, контент и процессы — разные коммиты.

### Перед коммитом

- `make validate` (и `make validate-mermaid`, если менялись mermaid-блоки) — зелёные.
- Индексы обновлены в том же коммите, что и контент: `index/<section>.yaml`,
  README раздела, основной README (счётчики).
- `verified` в каталоге `index/` отражает фактическую проверку: `executed` / `compiled` /
  `reviewed` / `none` — не обещание, а факт.
- `git status` — нет чужих файлов (`node_modules/`, временные артефакты).

### Разделение

- Файл с изменениями разных забот (например, manifest: новое поле + новые записи)
  разделяется на коммиты: сохранить финальную версию → вернуть HEAD → применить
  часть → коммит → применить остаток → коммит.
- Ошибка, найденная до коммита, — исправляется молча; найденная после — отдельный
  коммит (или `amend`, если коммит ещё не запушен).

### Push

- После коммита — push в `master` (PR-флоу в репозитории нет).
- Force-push в `master` — запрещён.

## Стиль

- Плотность сигнала: без вводных и повторов.
- Примеры кода важнее прозы.
- Правила в `rules.md` — краткие, с причиной.
- Версии: используйте закреплённые в `AGENTS.md`; если запись требует более новую — поднимите `min_version` и укажите в тексте.

## Языковые инструменты проверки

| Язык | Инструменты |
|---|---|
| Go | `gofmt`, `go vet`, `golangci-lint` |
| TypeScript | `tsc --strict`, `eslint` |
| JavaScript | `eslint` |
| Python | `ruff`, `mypy` |
| C | `clang -Wall -Wextra -Werror`, sanitizers |
| Bash | `shellcheck` |
