# FORMAT.md — спецификация формата записей

Единый источник правды о формате всех записей репозитория.
Перед созданием записи прочитайте этот документ полностью.

## Общие правила

- **Один файл = одна запись.** Имя файла: `kebab-case`, существительное, без префикса языка (язык определяется каталогом): `http-server.md`, а не `go-http-server.md`.
- Файлы: UTF-8, Markdown, завершаются символом новой строки.
- У каждой записи — YAML frontmatter (обязателен).
- Код в блоках всегда с указанием языка: ` ```go `, ` ```ts `, ` ```python `, ` ```c `, ` ```bash `.
- Код должен быть **компилируемым/запускаемым** и идиоматичным для закреплённой версии языка (см. `AGENTS.md`).
- Плотность сигнала: без воды. Примеры важнее описаний.

## Frontmatter (обязательные поля)

| Поле | Тип | Описание |
|---|---|---|
| `id` | string | Уникальный в репозитории: `<lang>-<name>`, напр. `go-http-server` |
| `title` | string | Человекочитаемое название |
| `lang` | string | `go` \| `typescript` \| `javascript` \| `python` \| `c` \| `bash` \| `shared` |
| `min_version` | string | Минимальная версия языка, напр. `"1.22"`, `"3.11"`, `"C23"`, `"5.2"` |
| `category` | string | `snippet` \| `pattern` \| `rule-set` \| `idioms` \| `decisions` \| `concept` |
| `tags` | [string] | 3–8 тегов, lowercase, для поиска |
| `status` | string | `stable` \| `experimental` \| `deprecated` |
| `updated` | date | Дата последнего содержательного обновления, `YYYY-MM-DD` |

## Каталог записей (`index/`)

- `index/manifest.yaml` — **шапка**: `version`, `updated`, `sections`
  (список разделов — для агентов и туллинга), версии языков
  (`languages.*.version`).
- `index/<section>.yaml` — **записи одного раздела** (go, typescript, …, shared,
  architecture, database, messaging, cicd). Агент читает только нужный файл.

Каждая запись:

| Поле | Тип | Описание |
|---|---|---|
| `id` | string | Совпадает с `id` в frontmatter файла |
| `title` | string | Совпадает с `title` в frontmatter файла |
| `path` | string | Путь к файлу относительно корня репозитория |
| `tags` | [string] | Теги для поиска (совпадают с frontmatter) |
| `status` | string | Совпадает со `status` в frontmatter |
| `verified` | string | Уровень проверки кода: `compiled` (скомпилирован/прогнан через type-check), `executed` (выполнен), `reviewed` (рецензирован, не компилировался), `none` (в записи нет кода) |
| `updated` | date | Дата последнего содержательного обновления; обязан совпадать с `updated` в frontmatter файла. Позволяет агенту/кешу проверять свежесть записи, не читая файл |

Правила:

- `id`, `title`, `status` обязаны совпадать с frontmatter — проверяется валидатором.
- `verified` отражает **факт проверки**, а не обещание: «код должен компилироваться» ≠ `compiled`.
- При повышении уровня проверки (например, `reviewed` → `compiled`) обновляйте
  `index/<section>.yaml` и дату `updated`.
- `updated` в записи каталога обязан совпадать с `updated` в frontmatter —
  проверяется валидатором. При содержательном изменении записи обновите обе.
- Имя секционного файла = название раздела; новые разделы — только после
  расширения `ALLOWED_SECTIONS` в `tools/validate.py`.

## Структура сниппета (category: snippet)

```markdown
# <Title>

**Когда использовать** — одна-две фразы.
**Когда НЕ использовать** — одна-две фразы + ссылка на альтернативу.

## Код
```<lang>
...
```

## Pitfalls
- Список типичных ошибок при использовании.

## Alternatives (опционально)
- Альтернативные подходы и когда они лучше.

## Related (опционально)
- Ссылки на связанные записи (относительные markdown-ссылки).
```

## Формат правил (rules.md, category: rule-set)

- Группировка по темам: `## Ошибки`, `## Именование`, `## Конкурентность` и т.д.
- Каждое правило — одна строка: `✅` (обязательно) или `❌` (запрещено) + суть + код-пример, если нужно.
- Правило без причины — плохое правило: указывайте следствие нарушения.
- `rules.md` — это **жёсткий** слой: агент обязан его соблюдать.

## Формат паттерна (category: pattern)

```markdown
# <Title>

**Проблема** — что решает паттерн.
**Решение** — суть в 2–4 предложениях.
**Когда использовать / Когда НЕ использовать**

## Код
Референсная реализация.

## Trade-offs
- Плюсы / минусы / альтернативы.

## Related
```

## Формат таблиц решений (decisions.md, category: decisions)

```markdown
## <Область, напр. HTTP>

| Задача | Рекомендация | Альтернатива | Когда |
|---|---|---|---|
| Роутинг | stdlib (1.22+) | chi | сложные мидлвари |
```

- Рекомендация — конкретная библиотека/подход + минимальная версия.
- «Когда» — условие, при котором выбирают альтернативу.

## Кросс-ссылки

- Только относительные markdown-ссылки.
- Из сниппета в паттерн: `../patterns/<name>.md`; между сниппетами: `<name>.md`.
- Битые ссылки запрещены.

## Статусы

- `stable` — рекомендуемая, проверенная на production.
- `experimental` — новая/нестабильная функциональность; помечать явно в тексте.
- `deprecated` — не использовать в новом коде; указать замену в frontmatter-комментарии и в тексте.
