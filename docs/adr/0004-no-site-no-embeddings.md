# 0004. Ни сайта, ни векторного поиска: файлы и каталог — единственный доступ

- **Статус:** accepted
- **Дата:** 2026-11-24

## Context

Библиотеку читают агенты: AGENTS.md → раздел → запись, поиск по тегам и
алиасам (`tools/find.py`, `make search`, MCP `search`/`get`). Периодически
возникает предложение добавить слой поверх: сгенерированный сайт (mkdocs и
аналоги), векторный индекс и «семантический» поиск, готовый JSON-дамп для RAG.

Проблема не в том, что это сложно, а в том, что это второй источник истины. У
репозитория уже был отказ того же класса: пин версии в `SKILL.md` поднимали
вручную, и блок CHANGELOG не вставлялся молча — два артефакта, которые обязаны
согласовываться, разъехались и никто не заметил. Сайт и эмбеддинги добавляют
ровно такую же пару: «текст записи» и «то, что из неё извлекли».

## Decision

1. **Источник истины — markdown в репозитории и `index/*.yaml`.** Никакого
   отдельного сайта: GitHub рендерит markdown, ссылки относительные работают и в
   редакторе, и в терминале, и в `get` у MCP.
2. **Поиск — по каталогу, не по содержимому всего репозитория**: `index/*.yaml`
   (теги, статус, `verified`) плюс алиасы из `index/aliases.yaml`. Ранжирование в
   `tools/find.py` общее для CLI и MCP, чтобы две точки входа не разъезжались.
3. **Векторного индекса нет.** Он требует пересборки на каждый коммит, хранит
   производные данные и выдаёт «похожий текст», а не «когда эту запись применять
   и когда не применять» — то, ради чего записи вообще снабжены разделами
   «Когда использовать / Когда НЕ использовать».
4. **Что допускается**: инструменты, которые *читают* каталог и ничего не пишут
   рядом с ним (`find.py`, `mcp_server.py`, `readme.py` — перегенерация блока
   таблицы в README из индексов, с проверкой в `make validate`).

## Consequences

- ✅ Один артефакт, никакого рассинхрона и никакой пересборки после коммита.
- ✅ Агент получает те же данные, что видит человек, включая статус `verified`.
- ❌ Плохая человеческая навигация: нет «похожих записей», нет поиска по тексту
  с подсветкой, нет фильтра по тегам в UI. Осознанно: читатель — агент.
- ❌ Поиск чувствителен к качеству тегов. Лечится проверкиами: теги обязаны
  совпадать с фронтоматтер-записью, а алиасы валидируются на дубли `id`.
- **Когда пересматривать:** когда записей станет порядок 1000 и разбор по тегам
  перестанет находить нужное. Тогда — эмбеддинги **по каталогу** (заголовок,
  теги, первый абзац «Когда использовать»), с инвалидацией по хэшу манифеста и
  с обязательной оговоркой, что это ускоритель, а не право пропустить чтение
  «Когда НЕ использовать».
