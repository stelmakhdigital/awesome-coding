# 0001. Agent-first дизайн: структура под чтение LLM-агентом

- **Статус:** accepted
- **Дата:** 2026-09-06

## Context

Репозиторий — база знаний для кодинг-агентов (LLM), а не только для людей.
Агент имеет ограниченный контекст: он не «прочитает всё», а точечно откроет
нужные файлы. Классическая структура «awesome-листа» (один длинный README со
ссылками) для этого не подходит: агенту приходится делать много лишних чтений,
а содержимое записей гетерогенно (код, правила, таблицы).

## Decision

1. **Один файл = одна запись** с предсказуемым именем (`kebab-case`) и
   машиночитаемым YAML frontmatter (`id`, `tags`, `status`, `updated`).
2. **`AGENTS.md` — роутер, а не контент**: таблица «задача → куда идти»,
   50–100 строк; агент читает его первым и дальше открывает только целевые файлы.
3. **Единый формат записей** (`docs/FORMAT.md`): «Когда использовать / Когда НЕ
   использовать» → код → pitfalls → related. Агент получает критерий выбора
   до того, как увидит код.
4. **Машиночитаемый каталог** (`index/manifest.yaml`): поиск по тегам без
   полнотекстового сканирования; валидатор держит каталог в синхроне с файлами.
5. **Высокая плотность сигнала**: таблицы и Do/Don't-пары вместо прозы;
   код-примеры минимальные и самодостаточные.

## Consequences

- ✅ Агент находит нужную запись за 1–2 чтения файлов; контекст тратится на суть.
- ✅ Человек получает ту же структуру (README → раздел → запись) — двойная аудитория.
- ✅ Валидация (frontmatter/manifest/ссылки) ловит дрейф каталога до мёрджа.
- ❌ Порог вступления выше: новая запись — это файл + frontmatter + manifest +
  index-таблица (4 места). Компенсируется валидатором и шаблонами в FORMAT.md.
- ❌ Формат жёсткий: «свободные заметки» в репозиторий не встраиваются —
  они уходят в ADR или `docs/`.
