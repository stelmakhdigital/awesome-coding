# LLM — таблицы решений

## Чем вызывать

| Задача | Рекомендация | Альтернатива | Когда |
|---|---|---|---|
| Один провайдер, прототип | SDK провайдера | — | быстрая итерация; следите за minor-обновлениями API |
| Продуктовый код, 2+ провайдера | **свой тонкий клиент поверх HTTP** | openai-compatible шлюз (LiteLLM и аналоги) | SDK тянет логику ретраев/стриминга, которую вы всё равно переопределяете |
| Нужна смена провайдера без правок | openai-compatible endpoint + конфиг | свой адаптер на провайдера | провайдеры сходятся на chat-completions-формате |
| Локальная / самостоятельно размещённая модель | тот же контракт через `base_url` | — | требования к данным «не наружу» |

Правило: клиент знает про **формат запроса и ответа**, не про «магию» провайдера.
Всё остальное (ретраи, бюджет, кэш, схема ответа) — ваш слой, он и тестируется.

## Модель

| Задача | Рекомендация | Когда |
|---|---|---|
| Классификация/извлечение по схеме | маленькая/дешёвая модель текущей версии | качество проверяется на evals, а не «на глаз» |
| Генерация длинного текста, план, код | модель выше классом, с фолбэком на дешёвую | фолбэк — по таймауту и по «не сошлась на схему» |
| Нужна воспроизводимость | закреплённый снапшот версии + температура 0 | «latest» и `temperature=1` несовместимы с тестами |
| Данные нельзя выносить | self-hosted/локальная модель | иначе — согласие и минимизация передаваемого |

## Структурированный вывод

| Задача | Рекомендация | Когда |
|---|---|---|
| Ответ идёт в код | схема (JSON schema / tools) + разбор по ней | всегда; «попросили JSON» — не контроль |
| Свободный текст пользователю | без схемы, но с лимитом токенов | — |
| Нужны числа/даты | строки в ответе + разбор с валидацией | модель не «число в JSON» надёжнее, чем кажется |

## Инструменты (модель выбирает действие)

| Задача | Рекомендация | Когда |
|---|---|---|
| Модель решает, что вызвать | цикл с инструментами и границами (раунды, токены, время) — [snippets/tool-calls.md](snippets/tool-calls.md) | без границ это счёт, а не фича |
| Операция одна и известна | схема без инструментов — [snippets/structured-output.md](snippets/structured-output.md) | инструменты дороже: round-trip плюс разбор ленты |
| Эффект необратим (платёж, удаление, письмо) | подтверждение человека перед вызовом | описание инструмента не является основанием выполнить |
| Локальный сервер или модель меньше | проверить, что tool calling вообще работает | «совместимые» сборки отвечают 200 и молча игнорируют `tools`: смотреть `finish_reason` |

## Стриминг

| Задача | Рекомендация | Когда |
|---|---|---|
| Ответ читает человек | стриминг (SSE) + отмена по закрытию клиента — [snippets/streaming.md](snippets/streaming.md) | латентность первого токена важнее суммы |
| Ответ идёт в код (в схему, в БД) | **без стриминга** | accumulating-парсер дороже, чем кажется: частичный JSON, склейка чанков, таймауты |
| Стриминг через прокси | буферизация выключена, heartbeat, явный дедлайн | nginx/ingress иначе «вешает» ответ |

## Где выполнять и где считать

| Что | Где |
|---|---|
| Секрет провайдера | только сервер; из браузера — через свой бэкенд |
| Подсчёт токенов и стоимости | свой слой: по `usage` ответа, в метриках, с моделью и версией промпта |
| Кэш | по ключу `модель + версия промпта + хеш входа`; Redis/файл, с TTL |
| Очередь на массовую обработку | своя очередь с ограничением параллелизма (см. [../go/snippets/rate-limit.md](../go/snippets/rate-limit.md)) |
| Хранение промптов/ответов | отдельное хранилище с TTL и перечнем данных, не «в общей таблице логов» |
